**核对结论**：Codex 昨日批次已落地全链路——web 设置面板「对话气泡颜色/透明度」（chatTint/chatOpacity）→ skin.js `KiminoPreviewChatStyle`（revision 防旧值覆盖）→ skin.css `data-kg-chat-custom` 规则；桌面端 Dream-Skin sanitize + `--agy-reply-alpha` + 设置工坊控件（atelier-chat-tint/atelier-chat-opacity/atelier-reply-opacity）+ host appearanceKeys。底部渐变 fade-host/mirror 底色从黑雾实验的 transparent **回退**到 `--kg-palette-base` 实底（黑雾根治实验回退，恢复 palette 实底视觉）。以上均未覆盖回旧状态，本批保持。

### A1. 真实缺陷修复（web，落盘未提交）

**桌宠台词气泡尾巴误读对话变量**：`.kimino-bubble::after` 两条规则引用 `--kg-chat-tint`（Gemini 对话系统的变量，无任何代码设置，恒落 fallback）——与主体固定色 `rgba(22,16,38,0.94)` 语义错位，未来对话变量一旦被设置会牵连桌宠尾巴。修复：尾巴与主体同为固定色。类别=独立真实 bug（桌宠台词气泡，非对话气泡）。

验证：`node Gemini-Web-Companion/test/bubble-tail-browser.cjs`（新增）——shadow DOM 内断言主体/尾巴同色、chat/bubble 变量注入不影响尾巴。PASS。

### A2. 双端一致性补齐：web 回答气泡独立透明度（replyOpacity，落盘未提交）

桌面已有 replyOpacity（`--agy-reply-alpha`，默认 glass 22%/否则 0）；web 完全缺失——模型回答只能跟随用户气泡。补齐 web 链路：

- skin.css：对话规则拆两条——用户消息/卡片走 `--kg-chat-alpha`，模型回答走 `--kg-reply-alpha`
- skin.js：storage keys += replyOpacity；`KiminoPreviewChatStyle(tint, opacity, reply)`（未设时**JS 置 reply=chat 值**，保持既有视觉，绕开 rgba() 内嵌套 var fallback 的兼容坑）；onChanged 跨标签页含 replyOpacity
- widget.js：设置面板加「回答气泡不透明度」滑条（默认「跟随用户气泡」），saveBubble 队列失败回退补 replyOpacity 恢复
- 边界：0=全透、100=不透、250 钳制为 1；`data-kg-chat-custom` 判定纳入 reply（只设 reply 也激活）

验证：`node Gemini-Web-Companion/test/chat-style-browser.cjs`（新增，7 项断言，mock 元素**非真实 Gemini 内容**）——默认回落/拆分生效/0 与 100/往返/onChanged/钳制。PASS。回归：runtime 22 项、bubble-tail、interaction 拖动摸头全绿。

### A3. 双端同步缺口修复（对话气泡外观 → 桌面 AGY 皮肤）

**真实发现**：web 调对话气泡颜色/透明度只写本地 storage——桌面桥接白名单（dreamSkin 桥接键）也不含 chatTint/chatOpacity/replyOpacity，双端联动核心特性在新功能上缺失。

修复（两端落盘）：
- 桌面 `main/index.cjs` 桥接 dreamSkin 白名单 += chatTint/chatOpacity/replyOpacity（null 透传给 sanitize 走默认）
- web `saveBubble` 支持本地成功后回调；对话气泡三个控件（颜色/用户透明度/回答透明度/重置）保存成功后推送 `KG_BRIDGE_PATCH {dreamSkin:{chatTint,chatOpacity,replyOpacity}}`（replyOpacity=null=跟随，桌面按自身默认处理）

验证（chat-style-browser step 10，sendMessage mock 记录）：滑条拖动 → patch 携带 `dreamSkin.replyOpacity=55` + chatOpacity/chatTint；重置 → patch 携带 `replyOpacity=null`。过程中修掉一个辅助函数边界 bug（`Number(null)=0` 被误判有效值）。回归：interaction/runtime/桌面 companion-visibility 全绿。

**已知语义差异（如实记录）**：web「跟随用户气泡」（null）→ 桌面落 sanitize 默认（glass 22%/否则 0），非字面跟随 web 的 chat 值；如需字面跟随需后续把桌面默认改为动态读取，涉及桌面语义变更，本批不擅自扩。
- **覆盖语义**：web 面板的对话气泡操作=用户主动交互，推送覆盖桌面 chatTint（最后写入胜，与桌面工坊同语义）。web 未操作时不推送，桌面设置不被动。
- **桌面→web 方向未做**：桌面工坊调 chatTint **不会**同步到 web 的对话气泡（web storage 独立）。是否加「对话气泡跟随桌面」开关（类 syncWallpaper 模式）属产品决策，本批未实现——如需要，在 skin.js loadAndApply 读 `bridgeState.desktop.chatTint` 优先即可。

### A4-b. 挂载竞态修复（第三个真实缺陷）

widget.js 挂载时的 storage keys（第 1181 行区）也漏 replyOpacity——挂载时两参 `applyChatStyle` 会 `removeProperty(--kg-reply-alpha)`，与 skin.js 的 loadAndApply 形成**时序竞态**：设置过回答透明度的用户重载页面后，模型回答底色可能闪烁或丢失。修复：挂载 keys += replyOpacity、挂载调用改三参。源码与 `--built` dist 双模式验证 PASS（dist 已重建）。

### A4-c. 跨标签页部分变更回归修复（第四个真实缺陷）

跨标签页只广播 chatTint 变更时，onChanged 回调第三参传 undefined → `removeProperty(--kg-reply-alpha)` → **其他标签页已设的回答透明度被静默清除**。修复：skin.js 记住最后已知 reply 值（`chatReply`），部分变更时以最后已知值补齐；widget.js 的 syncSettingsUI 同步改三参。新增 6b 回归步（reply=40 → 只广播 chatTint → reply 保持 0.4 且用户气泡随新 tint）。

## 类别 B：遗留说明与本批未覆盖

- **网页设置重开读回**：已实测（chat-style-browser step 8：加载完整 widget → 设置面板开/关/再开 → reply 滑条读回 40、跨标签页标签「40%」稳定）。过程中抓到并修复两个真实缺陷：**① `settingsKeys` 漏 replyOpacity**，syncSettingsUI 永远读不到该键而回退 chat 值；**② 重置路径缺失**——replyOpacity 一旦设置无法回到「跟随用户气泡」（没有任何 UI 途径清除）。修复：状态标签可点击重置（清除独立值、滑条跟随 chat、storage 写 null 清键），step 9 验证重置后 model 回落 0.76、标签恢复、存储清空。
- **主题导入导出**：已核对 catalog.json 条目键集合（credit/description/id/kind/name/pack/path/preview/sha256/size/updatedAt）——**replyOpacity 不在主题负载**（设计如此：主题=配色+壁纸透明度；回答透明度是外观设置，经 storage/跨标签页/桌面桥接 appearanceKeys 同步），导入导出路径不受影响。

- **Firefox 兼容记录**：manifest `strict_min_version=109`，但 skin.css 的对话气泡/等待区规则依赖 `:has()`（Firefox 121+ 才支持）——Firefox 109~120 上这些规则静默失效（既有状况，非本批引入；是否升 min 版本影响旧用户安装，留用户/Codex 决策）。
- **Web 壁纸轮播瞬切**（roadmap 待验）：真实瞬切依赖轮播节奏与后台标签页时序，mock 无法当真实轮播已验，维持「待真实轮播确认」不变。
