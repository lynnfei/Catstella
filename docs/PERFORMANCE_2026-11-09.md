# 系统操作迟缓排查

用户反馈：开启桌宠后疑似出现系统全局鼠标操作迟缓，尚不确定因果。此次只排查性能，自动碎碎念字号待办继续暂停。

## 发现和修复

- 旧窗口跟随程序在宿主可用时约每 16ms 轮询，多次重复查询 HWND、进程身份和窗口边界；位置事件又全局订阅了所有应用的事件。
- 改用 Windows 消息/父进程联合等待：焦点及位置事件及时唤醒，100ms 超时仅做兜底检查；进程身份和宿主枚举最多每秒复核一次，句柄失效/焦点变化及时处理。等待失败会退避，不进入忙循环。
- 位置事件只注册到已识别 AGY 宿主的进程和 UI 线程，切换宿主时注销旧监听；无有效 PID/线程时不退回全局订阅。
- 主进程忽略同一个跟随子进程中内容不变的重复心跳，减少重复窗口处理与界面快照。子进程身份变化后首条消息仍处理，心跳保活及故障恢复保留。

## 实测边界

同一机器各取 8 秒短时采样，按单核满载为 100%：原跟随程序约 12.1%，事件等待初版约 1.7%，收窄监听后约 0.8%。这是不同时间窗口的观测，没有固定其他应用工作负载，也没有测量实际输入延迟，不能据此认定所有全局卡顿均已解决。

采样时约 16GB 总内存、更新前可用约 2GB。主进程和其他应用仍有负载，若用户复测仍迟缓，应继续做桌宠开启/关闭的对照，检查系统内存、磁盘和合成开销；本轮没有终止其他应用或更改系统设置。
