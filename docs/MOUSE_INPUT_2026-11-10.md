# 全局鼠标移动迟滞复查

用户补充：单纯移动鼠标即强烈卡顿，在 Gemini Web 中观察到，未确认由网页引起。上轮降低跟随程序 CPU 的修复不能作为本问题已解决的证据。自动碎碎念字号待办继续暂停。

## 可复现的输入阻塞路径

旧代码多处调用 `setIgnoreMouseEvents(...,{forward:true})`。[Electron 45.1.0 的 Windows 实现](https://github.com/electron/electron/blob/v45.1.0/shell/browser/native_window_views_win.cc#L754) 为此在应用主线程安装系统级 `WH_MOUSE_LL` 钩子。它并不限于桌宠区域内的输入；窗口隐藏也不等于主动注销转发。因此，应用主线程阻塞可能通过这条路径影响其他软件的鼠标响应。

独立测试进程只识别测试器自己标记的事件，不记录真实鼠标内容，不点击或键入。四次交替一像素移动抵消位移。在相同 250ms 主线程负载下，旧转发开启的事件延迟为 229.659ms，关闭为 15.582ms；无人工负载时分别为 1.506ms、5.778ms。这证明此机制可放大系统输入延迟，不证明用户每次卡顿都只有同一原因。

## 修复

- Windows 上所有桌宠穿透设置统一经过 `MouseRouting`，始终关闭 `forward`，不使用 Electron 的全局鼠标转发钩子。
- 通过局部光标位置与异步 DOM 命中检查恢复交互。光标在窗口外不查询 DOM；窗口隐藏、用户设置完全穿透或正在拖动时不发起命中查询。查询串行，不积压任务；窗口销毁和拖动捕获后不应用迟到结果。
- 保留拖动、摸头、透明区域穿透与托盘驻留。非 Windows 延续原有路径。未修改 Web 源码、动画或字号。
